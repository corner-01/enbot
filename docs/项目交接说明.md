## 1. 项目是什么

EnBot 是储能业务智能客服后端，主要链路为：

```text
用户/前端/飞书
      │
      ▼
FastAPI 文本服务（8000）
      │
      ├─ 本地 Ollama 的 enbot-v9:7b，或 OpenAI 兼容接口
      ├─ 本机 RAG，或调用 B 机检索服务（8100）
      ├─ SSE 流式回答、来源返回、反馈记录
      └─ 可选图片诊断服务（8011）和 MCP 适配器（8020）
```

当前推荐的双机职责：

- A 机（主控机）：文本 API、生成模型、飞书、可选视觉服务和 MCP。
- B 机（检索 GPU 机）：Embedding、Milvus、BM25、RRF、Reranker 和知识库。
- A、B 机通过 `RETRIEVAL_API_KEY` 鉴权；两台机器必须配置相同值。

## 2. 首次部署

### 2.1 两台机器都执行

```powershell
git clone -b codex/optuna-retrieval-v1 <仓库地址>
Set-Location enbot
py -3.10 -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

不要把 `.env`、模型、真实密钥和反馈数据库提交到 Git。

### 2.2 B 机准备资产

把下列目录放到 B 机项目根目录：

```text
models/Qwen3-8B-native/
models/bge-reranker-v2-m3/
knowledge_data/
```

启动 Docker Desktop，然后首次建立索引：

```powershell
.\scripts\09_start_milvus.ps1
.\venv\Scripts\python.exe -X utf8 scripts\rebuild_milvus_index.py --check
.\venv\Scripts\python.exe -X utf8 scripts\rebuild_milvus_index.py --yes
```

### 2.3 A 机准备模型

将 V9 的 GGUF 放在本地，不提交 Git，然后导入 Ollama：

```powershell
ollama create enbot-v9:7b -f deployment\ollama-v9\Modelfile
ollama list
```

## 3. 日常启动顺序

### 3.1 先启动 B 机检索服务

```powershell
Set-Location D:\telebot
.\scripts\14_start_retrieval_gpu.ps1 `
  -ApiKey "<A、B 两机共用的长随机密钥>" `
  -HostAddress "0.0.0.0" `
  -Port 8100
```

健康检查：

```powershell
$h = @{"X-API-Key"="<同一密钥>"}
Invoke-RestMethod "http://127.0.0.1:8100/health/ready" -Headers $h
```

### 3.2 再启动 A 机文本服务

```powershell
Set-Location D:\telebot
.\scripts\13_start_primary_distributed.ps1 `
  -RetrievalApiUrl "http://<B机局域网IP>:8100" `
  -RetrievalApiKey "<同一密钥>" `
  -HostAddress "0.0.0.0" `
  -Port 8000 `
  -LlmProvider ollama `
  -OllamaModel "enbot-v9:7b"
```

A 机健康检查与接口页面：

```powershell
Invoke-RestMethod "http://127.0.0.1:8000/health/live"
Invoke-RestMethod "http://127.0.0.1:8000/health/ready"
```

- Swagger：`http://127.0.0.1:8000/docs`
- SSE：`POST /v1/chat/stream`
- 普通对话：`POST /v1/chat`
- 用户反馈：`POST /v1/feedback`

### 3.3 可选服务

```powershell
# 飞书长连接机器人
.\scripts\07_start_feishu_bot.ps1

# 图片诊断 API（8011）
.\scripts\11_start_vision_api.ps1


# MCP HTTP 适配器（8020，需要 venv-mcp）
.\scripts\14_start_mcp_http.ps1
```

## 4. 关键配置

| 配置 | 作用 |
|---|---|
| `LLM_PROVIDER` | `ollama` 使用本地模型；`openai` 使用 OpenAI 或兼容网关。 |
| `OLLAMA_MODEL` | 本地生成模型，当前推荐 `enbot-v9:7b`。 |
| `RETRIEVAL_MODE` | A 机设 `remote`；单机或 B 机设 `local`。 |
| `RETRIEVAL_API_URL` | A 机访问 B 机的地址，例如 `http://192.168.x.x:8100`。 |
| `RETRIEVAL_API_KEY` | A、B 机共用密钥，不得提交。 |
| `ENBOT_API_KEY` | 前端调用 8000 服务时的业务 API Key。 |
| `ENBOT_REQUIRE_MILVUS` | 生产建议 `true`，避免检索未就绪时仍宣称服务可用。 |
| `ENBOT_MODEL_ONLY` | `true` 时只用模型，不初始化 RAG。 |
| `ENBOT_WEB_SEARCH_ENABLED` | 默认 `false`，避免普通问题被外部搜索结果带偏。 |
| `KNOWLEDGE_FILE` | 新知识库目录，当前为 `./knowledge_data`。 |
| `MILVUS_COLLECTION` | 当前集合名 `enbot_knowledge_v1`。 |
| `FEISHU_BACKEND` | `rag` 调 EnBot API；`ollama` 绕过 RAG 直连模型。 |

## 7. 测试与验收

代码回归：

```powershell
.\venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
```

本次整理后的实测结果：主环境 `96` 项通过、`13` 项因视觉依赖在独立环境而跳过；随后在 `services/vision/.venv` 中运行视觉测试，`25` 项全部通过。

双机验收顺序：

1. B 机 `/health/ready` 返回 ready。
2. A 机 `/health/ready` 中 `retrieval_backend` 为 `remote`。
3. 调 `/v1/retrieve`，检查来源和 URL。
4. 调 `/v1/chat`，检查回答、`request_id`、`sources`。
5. 调 `/v1/chat/stream`，确认 `meta → heartbeat/delta → sources → done`。
6. 使用同一 `request_id` 调 `/v1/feedback`。
7. 最后再启动飞书，验证文本、图片和反馈闭环。
