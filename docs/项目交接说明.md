## 4. 关键配置

| 配置                         | 作用                                         |
| -------------------------- | ------------------------------------------ |
| `LLM_PROVIDER`             | `ollama` 使用本地模型；`openai` 使用 OpenAI 或兼容网关。  |
| `OLLAMA_MODEL`             | 本地生成模型，当前推荐 `enbot-v9:7b`。                 |
| `RETRIEVAL_MODE`           | A 机设 `remote`；单机或 B 机设 `local`。            |
| `RETRIEVAL_API_URL`        | A 机访问 B 机的地址，例如 `http://192.168.x.x:8100`。 |
| `RETRIEVAL_API_KEY`        | A、B 机共用密钥，不得提交。                            |
| `ENBOT_API_KEY`            | 前端调用 8000 服务时的业务 API Key。                  |
| `ENBOT_REQUIRE_MILVUS`     | 生产建议 `true`，避免检索未就绪时仍宣称服务可用。               |
| `ENBOT_MODEL_ONLY`         | `true` 时只用模型，不初始化 RAG。                     |
| `ENBOT_WEB_SEARCH_ENABLED` | 默认 `false`，避免普通问题被外部搜索结果带偏。                |
| `KNOWLEDGE_FILE`           | 新知识库目录，当前为 `./knowledge_data`。             |
| `MILVUS_COLLECTION`        | 当前集合名 `enbot_knowledge_v1`。                |
| `FEISHU_BACKEND`           | `rag` 调 EnBot API；`ollama` 绕过 RAG 直连模型。    |

## 7. 测试与验收

代码回归：

```powershell
.\venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
```

本次整理后的实测结果：主环境 `96` 项通过、`13` 项因视觉依赖在独立环境而跳过；随后在 `services/vision/.venv` 中运行视觉测试，`25` 项全部通过。

双机验收顺序：

1. B 机 `/health/ready` 返回 ready。
2. A 机 `/health/ready` 中 `retrieval_backend` 为 `remote`。
3. 调 `/v1/retrieve`，检查来源和 URL。
4. 调 `/v1/chat`，检查回答、`request_id`、`sources`。
5. 调 `/v1/chat/stream`，确认 `meta → heartbeat/delta → sources → done`。
6. 使用同一 `request_id` 调 `/v1/feedback`。
7. 最后再启动飞书，验证文本、图片和反馈闭环。
